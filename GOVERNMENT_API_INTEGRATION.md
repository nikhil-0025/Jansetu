# JanSetu (जनसेतु) — Indian Government API Integration Layer
> **Authorized Government Services, DigiLocker Partner Gateway, API Setu, and Open Data Architecture**  
> **Platform:** JanSetu Unified Citizen Welfare Platform  
> **Tagline:** *Har Parivaar, Har Haq, Ek Setu (हर परिवार, हर हक, एक सेतु।)*

## 🏛️ 1. Executive Summary & Architectural Philosophy

JanSetu establishes a unified, accessible digital bridge between citizens, household units, family relationship graphs, and authorized Indian public welfare schemes. To verify citizen entitlements without creating proprietary information silos or exposing sensitive citizen records, JanSetu implements an **Authorized Indian Government API Integration Layer**.

### Core Architectural Guardrails:
1. **No Invented APIs or Phantom Authorizations:** Every candidate endpoint is modeled directly on authentic documentation from [API Setu](https://apisetu.gov.in/), [DigiLocker Partner Portal](https://api.apisetu.gov.in/), [Open Government Data Platform](https://data.gov.in/), and [myScheme](https://www.myscheme.gov.in/).
2. **Strict Separation of Public Open Data from Sensitive PII:**
   - **Public Open Datasets (data.gov.in, myScheme):** Macro-level scheme stats, district allocations, and eligibility criteria are queried without capturing or transmitting Personally Identifiable Information (PII).
   - **Citizen-Sensitive Verification APIs (API Setu / DigiLocker):** Certificate verification and document pulls strictly require an **Electronic Consent Artifact** compliant with India's **Digital Personal Data Protection (DPDP) Act, 2023**.
3. **No False Claims of Verification:** Only responses received from authorized government endpoints with verifiable cryptographic signatures are marked as `Authoritative Government Verified`. Responses generated by the local demonstration adapter are explicitly stamped `Simulated Demonstration Record (Non-Authoritative)`.
4. **Local Family ID Disclaimer:** JanSetu generates system-level Family IDs (e.g. `FAM-1001`, `FAM-2001`) to track shared cooking hearths, ration units, and dwelling partitions. These are **Local JanSetu System Household Accounts** and are **never** represented as official government-issued national identifiers.
5. **Human-in-the-Loop Governance:** Incomplete API data or potential duplicate flags never cause automatic exclusion or rejection. Questionable cases are routed to the **Block Development Officer Verification Queue** with explainable decision recommendations.
6. **Decoupled Fallback:** The application functions with 100% feature availability in offline / zero-credential mode via a high-fidelity **JanSetu Simulated Mock Adapter**.

## 🚦 2. Real-Time Connection States Report

Every integrated service in JanSetu operates under one of five strictly defined connection states:

| Connection State | Description | Active Condition | Security & Data Handling |
| :--- | :--- | :--- | :--- |
| **`CONNECTED`** | Production credentials active. | Valid `APISETU_CLIENT_ID` & `APISETU_API_KEY` connecting to live endpoints (`https://apisetu.gov.in/`). | Mutual TLS / Header-based HMAC; authoritative verification. |
| **`SANDBOX`** | Official staging environment. | Sandbox credentials configured connecting to `https://apisetu.gov.in/developer/sandbox`. | Test datasets provided by issuer departments. |
| **`AWAITING_APPROVAL`** | Entity registered; category pending. | Institutional use-case submitted on `partners.apisetu.gov.in`; awaiting department review. | Sandbox access permitted; live consumption disabled. |
| **`UNAVAILABLE`** | Endpoint unreachable or tripped. | Network timeout (>6000ms), DNS failure, upstream 5xx, or circuit breaker open. | Gracefully falls back to mock adapter with warning. |
| **`DEMO_MODE`** | Zero credentials / local test. | No environment keys present (`GOV_API_FORCE_MOCK=true` or blank keys). | Mock adapter returns realistic, clearly labeled simulated records. |

## 📋 3. Government API Integration Inventory

### Service 1: National / State e-PDS Ration Card Verification API
- **Identifier:** `APISETU-EPDS-RATION`
- **Publisher:** Department of Food and Public Distribution, Ministry of Consumer Affairs / State Civil Supplies (e.g., FCS UP, Civil Supplies Kerala).
- **Portal Source:** API Setu ([https://apisetu.gov.in/](https://apisetu.gov.in/))
- **Live Endpoint:** `POST https://apisetu.gov.in/fcs/v3/ratcr/certificate`
- **Sandbox Endpoint:** `POST https://apisetu.gov.in/developer/sandbox/fcs/v3/ratcr/certificate`
- **Purpose:** Verifies authentic ration card category (Antyodaya AAY, BPL, Priority Household PHH), Fair Price Shop (FPS) allocation, and registered household members to validate food subsidy eligibility and ancestral dwelling co-residence.
- **Authentication:** HTTP Headers `X-APISETU-CLIENTID` and `X-APISETU-APIKEY`.
- **Consent Requirements:** Mandatory. Generates API Setu v3 Electronic Consent Artifact capturing citizen identity, verification purpose, and SHA-256 digest.
- **Approval Requirements:** Registered consumer entity on `partners.apisetu.gov.in` with organization PAN/GST, formal scheme use-case submission, and MoU/approval from the respective State Civil Supplies Department.
- **Sandbox Availability:** Available via API Setu developer sandbox.
- **Data Returned:**
  ```json
  {
    "rationCardNumber": "UP-VAR-2023-9182741",
    "cardCategory": "Priority Household (PHH / NFSA)",
    "headOfFamily": "Rahul Sharma",
    "fpsCode": "FPS-UP-VAR-4402",
    "members": [
      { "name": "Rahul Sharma", "relationship": "Head", "age": 38, "uidLinked": true },
      { "name": "Amit Sharma", "relationship": "Brother", "age": 29, "uidLinked": true }
    ],
    "monthlyEntitlement": { "wheatKg": 10, "riceKg": 10 }
  }
  ```

### Service 2: State Electricity Distribution Utility (DISCOM) Dwelling Verification API
- **Identifier:** `APISETU-DISCOM-ELECTRICITY`
- **Publisher:** State Electricity Distribution Companies (e.g. Purvanchal Vidyut Vitaran Nigam Ltd / UPPCL Uttar Pradesh, Mahadiscom Maharashtra).
- **Portal Source:** API Setu ([https://apisetu.gov.in/](https://apisetu.gov.in/))
- **Live Endpoint:** `POST https://apisetu.gov.in/uppcl/v3/elctc/certificate`
- **Sandbox Endpoint:** `POST https://apisetu.gov.in/developer/sandbox/uppcl/v3/elctc/certificate`
- **Purpose:** Authoritatively verifies independent electrical service connection, consumer account, meter number, and physical dwelling address for household separation (Scenario A) to verify physical dwelling partition.
- **Authentication:** HTTP Headers `X-APISETU-CLIENTID` and `X-APISETU-APIKEY`.
- **Consent Requirements:** Mandatory. Requires electronic consent artifact with purpose code `INDEPENDENT_DWELLING_VERIFICATION`.
- **Approval Requirements:** DISCOM service subscription approval via API Setu Partner Portal.
- **Sandbox Availability:** Available via API Setu developer sandbox.
- **Data Returned:**
  ```json
  {
    "consumerNumber": "1029384756",
    "consumerName": "Amit Sharma",
    "premisesAddress": "House No. 42B, Shanti Nagar, Sevapuri, Varanasi, UP - 221403",
    "connectionType": "Domestic (LMV-1)",
    "meterNumber": "MTR-UPPCL-88912",
    "connectionStatus": "Live / Active",
    "sanctionedLoadKw": 2.0
  }
  ```

### Service 3: DigiLocker Partner Gateway Document Pull & URI Resolution API
- **Identifier:** `DIGILOCKER-PULL-DOCUMENT`
- **Publisher:** National e-Governance Division (NeGD) / Ministry of Electronics & IT (MeitY).
- **Portal Source:** DigiLocker Partner Portal ([https://api.apisetu.gov.in/](https://api.apisetu.gov.in/))
- **Live Endpoint:** `POST https://api.apisetu.gov.in/v1/digilocker/pull-doc`
- **Sandbox Endpoint:** `POST https://api.apisetu.gov.in/sandbox/v1/digilocker/pull-doc`
- **Purpose:** Allows citizens to authenticate and pull tamper-evident, digitally signed certificates (Income Certificate, Caste Certificate, Domicile, Land Records) directly into the JanSetu Document Vault.
- **Authentication:** OAuth 2.0 / Requester Token + `X-APISETU-CLIENTID` and `X-APISETU-APIKEY`.
- **Consent Requirements:** Mandatory. Citizen consent scope granted under Information Technology (Digital Locker) Rules, 2016.
- **Approval Requirements:** Registration as Requester Organization on DigiLocker Partners, document schema whitelisting, and security compliance audit.
- **Sandbox Availability:** Fully supported with mock fallback.
- **Data Returned:**
  ```json
  {
    "documentUri": "in.gov.up.edistrict-INC-9281729",
    "documentTitle": "Income Certificate (Revenue Dept)",
    "beneficiaryName": "Rahul Sharma",
    "issuingAuthority": "Sub-Divisional Magistrate (SDM), Varanasi",
    "digitalSignature": {
      "status": "VALID_GOVERNMENT_SEAL",
      "digestAlgorithm": "SHA-256"
    },
    "fileUrl": "/uploads/sample_verified_doc.pdf"
  }
  ```

### Service 4: Open Government Data (OGD) Platform India — Public Scheme Datasets
- **Identifier:** `OGD-DATA-GOV-PUBLIC-SCHEMES`
- **Publisher:** National Informatics Centre (NIC) / Ministry of Consumer Affairs, Food & Public Distribution.
- **Portal Source:** Open Government Data Platform India ([https://data.gov.in/](https://data.gov.in/))
- **Live Endpoint:** `GET https://api.data.gov.in/resource/{RESOURCE_ID}?api-key={API_KEY}&format=json&limit=5`
- **Purpose:** Ingests macro-level welfare scheme benchmarks, state-level allocations, National Food Security Act (NFSA) beneficiary distribution statistics, and PMAY-G completion statistics.
- **Authentication:** URL Query Parameter `api-key` (Obtained through free developer registration on data.gov.in).
- **Consent Requirements:** **None.** Governed by National Data Sharing and Accessibility Policy (NDSAP), 2012. Completely public aggregated data; contains zero PII.
- **Approval Requirements:** Self-service registration on data.gov.in.
- **Sandbox Availability:** Free developer API keys available instantly.
- **Data Returned:**
  ```json
  {
    "state": "Uttar Pradesh",
    "district": "Varanasi",
    "block": "Sevapuri",
    "nfsa_covered_families": 48920,
    "pmay_g_constructed_houses": 4120,
    "active_disbursement_cycle": "FY 2026-27 Q2"
  }
  ```

### Service 5: myScheme National Welfare Marketplace & Taxonomy API
- **Identifier:** `MYSCHEME-NATIONAL-CATALOG`
- **Publisher:** Ministry of Electronics & IT (MeitY) / NeGD / Digital India Corporation.
- **Portal Source:** myScheme ([https://www.myscheme.gov.in/](https://www.myscheme.gov.in/))
- **Live Endpoint:** `GET https://api.myscheme.gov.in/api/v1/schemes`
- **Purpose:** Discovers national and state welfare schemes, eligibility rule parameters (income ceilings, landholding limits, dwelling requirements), required supporting documents, and official nodal ministry guidelines.
- **Authentication:** Standard API Key / Open Catalog Discovery Schema.
- **Consent Requirements:** **None.** Public welfare information designed for open citizen discovery.
- **Approval Requirements:** Institutional access via API Setu partner program.
- **Sandbox Availability:** Catalog feed and mock fallback available.

## 🛠️ 5. Setup & Configuration Guide

### Step 1: Environment Variables
Copy `.env.example` to `.env` and configure your credentials:

```bash
# General
PORT=5000
MONGODB_URI=mongodb://localhost:27017/jansetu
JWT_SECRET=jansetu_super_secure_jwt_secret_key_2026
NODE_ENV=development

# Government Integration Mode
# Set to 'true' to force mock adapter even if keys are present (for offline demos)
GOV_API_FORCE_MOCK=false
GOV_API_TIMEOUT_MS=6000
GOV_API_RETRY_ATTEMPTS=2

# 1. API Setu Credentials (from https://partners.apisetu.gov.in)
APISETU_BASE_URL=https://apisetu.gov.in
APISETU_SANDBOX_URL=https://apisetu.gov.in/developer/sandbox
APISETU_ENV=sandbox
APISETU_CLIENT_ID=in.gov.your_org_client_id
APISETU_API_KEY=your_secret_api_key_here

# 2. Open Government Data Platform India (from https://data.gov.in)
DATA_GOV_BASE_URL=https://api.data.gov.in/resource
DATA_GOV_API_KEY=your_free_datagov_api_key_here

# 3. DigiLocker Partner Gateway
DIGILOCKER_PARTNER_ID=your_partner_id
DIGILOCKER_API_SECRET=your_partner_secret
```

> [!IMPORTANT]
> **Zero Credential Operation:** If no keys are provided, JanSetu automatically operates in `DEMO_MODE`. The application will remain fully functional with all tests, workflows, and UI views executing cleanly using the labeled mock adapter.

## 🛡️ 7. Statutory Governance Compliance Matrix

| Governance Requirement | How JanSetu Implements & Enforces It |
| :--- | :--- |
| **No Invented APIs or False Endpoints** | Strictly follows authentic API Setu v3, DigiLocker Partner, data.gov.in, and myScheme schemas. Endpoints and parameters match official specs. |
| **Clear Separation of Public vs PII** | Public macro datasets (data.gov.in, myScheme) require no citizen consent. Citizen identity/dwelling checks strictly require signed DPDP Act consent artifacts. |
| **Authoritative Verification Truthfulness** | Responses are stamped with `isAuthoritative` and `isSimulated`. Mock adapter results are labeled `Simulated Demonstration Record (Non-Authoritative)`. |
| **Local Family ID Truthfulness** | Seed and newly created households have `identifierType: "Local JanSetu System Household ID (Not an official National Family ID)"`. The UI displays a clear "Local System ID" badge. |
| **Multi-Source Entitlement Logic** | Does not assume a single API provides household membership, separation, benefits, and eligibility. Separates identity (DigiLocker), dwelling (DISCOM), ration (e-PDS), and rules (myScheme). |
| **No Automated Exclusion / Rejection** | Incomplete API responses or duplicate flags leave applications in `Pending Verification` with officer action recommended; never auto-rejects poor citizens. |
| **Backend Secret Isolation** | API keys and client secrets reside exclusively in backend environment variables. All diagnostic endpoints use `getMaskedGovConfig()` to mask secrets (`abc...xyz`). |
